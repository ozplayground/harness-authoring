# harness-audit — 스킬·에이전트 정의를 검사해 후보를 낸다

판정 기준은 스킬 작성 규칙과 에이전트 작성 규칙이다. 검사 전에 둘을 불러 둔다.

## 절차

1. **기계 검사.**

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/check_frontmatter.py <하네스 루트>     # frontmatter 없음, 따옴표 없는 값 안의 ': ', ':'로 끝나는 값
   python3 ${CLAUDE_SKILL_DIR}/scripts/check_cross_refs.py <skills 디렉터리>  # 스킬 본문·description에 나온 다른 스킬 이름
   ```

   `check_cross_refs.py`의 결과는 후보다. 옵션 값이나 파일명과 우연히 겹친 것을 걸러 낸다.

2. **문장 검사.** 파일을 끝까지 읽는다. 스킬은 먼저 방법론 스킬인지 도구 스킬인지 정하고 보고에 적는다. 스킬 파일은 스킬 작성 규칙에, 에이전트 정의는 에이전트 작성 규칙에 문장마다 대어 본다. 규칙에 어긋나는 문장을 후보로, 규칙만으로 판정이 갈리는 문장을 애매로 적는다.

3. **도구 동작 서술 검사.** "반영된다/안 된다", "고정된다", "로드된다", "읽힌다"처럼 도구의 동작을 단정하는 문장마다 실험이나 공식 문서의 근거가 있는지 본다. 없으면 후보로 올리고, `${CLAUDE_SKILL_DIR}/references/probe.md`의 어느 실험으로 확인할지 적는다. 검사 중에 실험하지 않는다.

4. **보고.** 아래 형식으로.

## 보고 형식

```markdown
## 스킬 종류
| 스킬 | 종류 (방법론 / 도구) | 판단 근거 한 줄 |
|---|---|---|

## 기계 검사
- check_frontmatter: <n>건 (목록)
- check_cross_refs: 후보 <n>건 중 실제 호출 <m>건 (목록), 값·파일명 <k>건

## 후보
| 파일:줄 | 원문 | 어긋난 규칙 | 사유 한 줄 |
|---|---|---|---|

## 애매
| 파일:줄 | 원문 | 갈리는 이유 |

## 확인하지 못한 도구 동작 서술
| 파일:줄 | 문장 | 확인할 실험 |

## 확인하지 못한 것
```

후보에는 원문을 그대로 인용한다. 요약하지 않는다. 절에 해당하는 것이 없으면 "없음"이라고 쓴다.

## 하지 않는 것

- 파일 고치기
- 작성 규칙에 없는 기준(취향, 문체)으로 후보 올리기
- 검사 중에 실험하기
